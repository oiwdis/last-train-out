# Build 111 cold High native Metal crash

The third cold start in the mixed native Metal series exited with signal 11 after 16.41 seconds. This was High, with a fresh application cache. Apple recorded `EXC_BAD_ACCESS` on a pipeline worker. The engine emitted no preceding validation error. The operating-system report and all other processes from the series are retained. [Original mixed series and Apple report](mixed-series.zip) · [CI job](https://github.com/oiwdis/last-train-out/actions/runs/44859769512/job/136716175279)

The packaged native binary has SHA-256 `bc06ab5d56e536bd1c6ad8dabaf226109ce841bf7273ae6ef0f1b91e4c292a04`. The instruction at `RenderingDevice::render_pipeline_create + 1100` reads a null entry while looking up a vertex-format identifier. The following two lookups and the identifier type match the vertex-format table in the pinned source. The render thread was compiling new mesh-surface formats concurrently. `vertex_format_create` takes Godot’s device mutex to update the table. In 4.5.1 the pipeline worker read the same table without that mutex. The observed signal and stack differ from the MoltenVK command-buffer timeout in the stock player. [Pinned pipeline reader](https://github.com/godotengine/godot/blob/f62fdbde15035c5576dad93e586201f4d41ef0cb/servers/rendering/rendering_device.cpp#L4016) · [Pinned format writer](https://github.com/godotengine/godot/blob/f62fdbde15035c5576dad93e586201f4d41ef0cb/servers/rendering/rendering_device.cpp#L3144)

The native template now takes the existing device mutex while obtaining and validating the vertex description, releases it before driver pipeline creation and retains the validation error for a missing format. The additional macOS test runs the ordinary High workload with the original and rebuilt executable against copies of the exact build 111 PCK, source caches and libraries. The current universal package also runs the established three native stress series and its own gameplay, visual and frame-time gates.
